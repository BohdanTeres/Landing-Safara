### Опис реалізації
У ході виконання лабораторної роботи було створено програму мовою Java, яка реалізує інтерпретатор мови Small BASIC. Проєкт має модульну структуру та складається з кількох основних класів.

Клас Main є точкою входу до програми. Він відповідає за завантаження тексту програми з файлу та запуск інтерпретатора. У цьому класі також обробляються можливі помилки виконання.

Основна логіка інтерпретатора реалізована у класі SBasic. У цьому класі містяться методи для аналізу та виконання операторів, обробки виразів, а також керування потоком виконання програми. Клас використовує масив символів для збереження програми та індекс, який вказує на поточну позицію в коді.

Для обробки помилок використовується окремий клас InterpreterException, який дозволяє виводити зрозумілі повідомлення про помилки під час виконання програми.

### Лексичний аналіз
Лексичний аналіз здійснюється методом `getToken()`, який послідовно зчитує символи програми та формує лексеми. У процесі роботи цей метод визначає тип лексеми, зокрема:

* числа
* змінні
* ключові слова
* оператори
* рядки у лапках

Це дозволяє інтерпретатору правильно розпізнавати структуру програми та передавати дані для подальшої обробки.

---

### Синтаксичний аналіз

Синтаксичний аналіз реалізовано за допомогою рекурсивного спуску. Основним методом є `evaluate()`, який запускає процес обчислення виразу.

Далі викликаються допоміжні методи, кожен з яких відповідає за певний рівень пріоритету операцій. Наприклад, методи `evalExp2()` та `evalExp3()` обробляють додавання, віднімання, множення та ділення відповідно.

Такий підхід дозволяє забезпечити правильний порядок виконання операцій і підтримує складні вкладені вирази.


---

### Робота зі змінними
У програмі змінні представлені у вигляді масиву типу `double`, де кожна змінна відповідає певній літері латинського алфавіту. Це дозволяє швидко отримувати доступ до значення змінної та змінювати його під час виконання програми.

---

### Реалізація операторів
Інтерпретатор підтримує основні оператори мови Small BASIC. Зокрема, оператор `PRINT` використовується для виведення значень на екран, а `INPUT` — для введення даних з клавіатури.

Оператор `IF THEN` дозволяє виконувати умовні переходи залежно від результату логічного виразу. Якщо умова не виконується, інтерпретатор переходить до наступного рядка програми.

Цикл `FOR/NEXT` реалізований із використанням стеку, що дозволяє підтримувати вкладені цикли. При кожному вході в цикл зберігається інформація про змінну-лічильник, граничне значення та позицію в коді.

Оператори `GOTO`, `GOSUB` та `RETURN` забезпечують керування потоком виконання програми. Для цього використовується таблиця міток (`TreeMap`), яка дозволяє швидко знаходити потрібну позицію в коді.


---
### Обробка помилок

Для обробки помилок використовується спеціальний механізм винятків. У разі виникнення помилки інтерпретатор генерує об’єкт класу `InterpreterException`, який містить опис проблеми. Це дозволяє користувачу отримати зрозуміле повідомлення та спростити налагодження програми.

**Приклад 1: Обробка арифметичних виразів**

```java
private double evalExp2() throws InterpreterException {
    char op;
    double result = evalExp3();

    while ((op = token.charAt(0)) == '+' || op == '-') {
        getToken();
        double partial = evalExp3();
        if (op == '+') result += partial;
        else result -= partial;
    }
    return result;
}
```

Цей код реалізує обробку операцій додавання та віднімання з урахуванням пріоритетів.
AI використовувався для оптимізації структури рекурсивного аналізу.

**Приклад 2: Реалізація оператора IF**

```java
private void execIf() throws InterpreterException {
    double result = evaluate();
    getToken();

    if (result == 0) {
        findEOL();
    }
}
```

Було використано AI для спрощення логіки умовного переходу.
Рішення дозволяє пропускати оператор, якщо умова хибна.

**Приклад 3: Реалізація циклу FOR**

```java
private void execFor() throws InterpreterException {
    ForInfo f = new ForInfo();

    getToken();
    f.var = Character.toUpperCase(token.charAt(0)) - 'A';

    getToken();
    vars[f.var] = evaluate();

    getToken();
    f.target = evaluate();

    f.loc = progIdx;
    fStack.push(f);
}
```
AI допоміг структурувати логіку ініціалізації циклу та збереження стану у стеку.

---

**Приклад 4: Обробка PRINT**

```java
private void print() throws InterpreterException {
    do {
        getToken();

        if (tokType == QUOTEDSTR) {
            System.out.print(token);
        } else {
            putBack();
            System.out.print(evaluate());
        }

        getToken();

    } while (token.equals(",") || token.equals(";"));

    System.out.println();
}
```
Було реалізовано підтримку виведення кількох значень через , та ;.
AI допоміг правильно організувати цикл обробки аргументів.

```java
private void execGoto() {

    }
}
```

## Завдання на захист
## Twelve-Factor App — описати 12 факторів за 12factor.net. Визначити, які фактори застосовні до CLI-застосунків типу інтерпретатора (конфігурація, логування, залежності) та як їх реалізувати в проекті.

Аналіз 12 факторів
1. Codebase

Даний принцип передбачає використання одного репозиторію для одного застосунку.

У моєму проєкті весь код інтерпретатора знаходиться в одному Gradle-проєкті:
```
SmallBasicInterpreter/
├── src/
├── build.gradle
└── settings.gradle
```
Це спрощує підтримку та дозволяє централізовано керувати всіма компонентами програми.

2. Dependencies

Усі залежності повинні бути явно визначені.

Для керування залежностями я використав систему Gradle.

Файл build.gradle
```gradle
plugins {
    id 'java'
    id 'application'
}

group = 'ua.edu.tntu'
version = '1.0'

application {
    mainClass = 'ua.edu.tntu._121_se.sbasic.Main'
}
```
Опис реалізації

У цьому файлі я підключив плагіни java та application, які дозволяють:

компілювати програму;
запускати застосунок;
автоматизувати процес збірки.

Також я визначив головний клас Main, який є точкою входу до програми.

Завдяки Gradle проєкт можна запускати однаково:

в IntelliJ IDEA;
через термінал;
на іншому комп’ютері.

Запуск виконується командою:

gradlew run
3. Config

Конфігурація повинна бути відокремлена від програмного коду.

У моєму інтерпретаторі конфігурацією є:

ім’я .bas файлу;
параметри запуску;
режим роботи програми.
Реалізація
```java
String file = System.getenv("SBASIC_PROGRAM");

if (file == null) {
    file = "test1.bas";
}
```

У цьому фрагменті я реалізував отримання імені тестової програми через змінну середовища SBASIC_PROGRAM.

Якщо змінна середовища не задана, автоматично використовується файл test1.bas.

Такий підхід дозволяє змінювати конфігурацію без редагування вихідного коду програми.

Приклад запуску:
```
set SBASIC_PROGRAM=test2.bas
gradlew run
```
4. Backing Services

Принцип Backing Services передбачає підключення зовнішніх сервісів як окремих ресурсів.

Для консольного інтерпретатора цей принцип використовується частково, оскільки програма не працює з базами даних або веб-сервісами.

Проте у майбутньому можна додати:

систему логування;
зовнішнє сховище програм;
API для компіляції або перевірки коду.
5. Build, Release, Run

Етапи збірки, створення релізу та запуску повинні бути розділені.

Реалізація
Збірка:
gradlew build
Запуск:
gradlew run
Створення JAR:
gradlew jar
Опис реалізації

Для реалізації цього принципу я використав можливості Gradle.
Збірка проєкту відбувається окремо від запуску, що дозволяє:

створювати готові .jar файли;
переносити програму на інші комп’ютери;
стандартизувати процес запуску.
6. Processes

Застосунок не повинен зберігати стан між запусками.

У моєму інтерпретаторі всі змінні створюються заново при кожному запуску:

vars = new double[26];

Після завершення роботи програми всі дані очищаються автоматично.

7. Port Binding

Програма повинна самостійно надавати сервіси через порти.

Для CLI-застосунку цей фактор не є актуальним, оскільки інтерпретатор працює локально через консоль.

8. Concurrency

Масштабування повинно виконуватись через процеси.

У поточній реалізації інтерпретатор працює в одному потоці, однак за необхідності можна реалізувати:

багатопотокове виконання;
паралельний запуск кількох програм.
9. Disposability

Програма повинна швидко запускатися та завершувати роботу.

Мій інтерпретатор запускається практично миттєво та не потребує складної ініціалізації. Це особливо важливо під час:

тестування;
налагодження;
багаторазового запуску програм.
10. Dev/Prod Parity

Середовище розробки та виконання повинні бути максимально схожими.

Завдяки Gradle:

запуск у IntelliJ IDEA;
запуск через термінал;
запуск на іншому комп’ютері

відбувається однаково.

Це дозволяє уникнути проблем із різними середовищами виконання.

11. Logs

Логи повинні виводитися як потік подій.

Реалізація
```java
private void log(String message) {
    System.out.println("[LOG] " + message);
}
```
Використання
```java
log("Running program");
```
Опис реалізації

Для логування я реалізував окремий метод log(), який виводить повідомлення у консоль із префіксом [LOG].

Це дозволяє:

відстежувати виконання програми;
бачити поточний стан інтерпретатора;
швидше знаходити помилки.

Під час запуску програми виводяться повідомлення:

про старт програми;
виконання операторів;
завершення роботи.
12. Admin Processes

Адміністративні задачі повинні запускатися окремо.

Для інтерпретатора такими задачами є:

тестування;
запуск прикладів;
генерація звітів;
збірка .jar файлів.
Приклад інтеграції принципів Twelve-Factor App
Оновлений Main.java
```java
package ua.edu.tntu._121_se.sbasic;

import java.io.InputStream;
import java.nio.charset.StandardCharsets;

public class Main {

    public static void main(String[] args) {

        String file = System.getenv("SBASIC_PROGRAM");

        if (file == null) {
            file = "test1.bas";
        }

        try {

            InputStream is = Main.class
                    .getClassLoader()
                    .getResourceAsStream(file);

            if (is == null) {
                System.out.println("Program not found: " + file);
                return;
            }

            String program = new String(
                    is.readAllBytes(),
                    StandardCharsets.UTF_8
            );

            System.out.println("[LOG] Running program: " + file);

            SBasic sb = new SBasic(program);
            sb.run();

            System.out.println("[LOG] Program finished.");

        } catch (Exception e) {
            System.out.println("[ERROR] " + e);
        }
    }
}
```
Опис реалізації Main.java

У цьому класі:

завантаження .bas файлу;
зчитування конфігурації через змінні середовища;
систему логування;
обробку помилок.

Файл програми завантажується через ClassLoader, що дозволяє працювати з ресурсами Gradle-проєкту.

Також було реалізовано виведення повідомлень про запуск та завершення роботи інтерпретатора.

# Висновки
У ході виконання лабораторної роботи було розроблено інтерпретатор мови програмування Small BASIC мовою Java та реалізовано повний цикл обробки програми: лексичний аналіз, синтаксичний аналіз і виконання операторів. Для обробки арифметичних виразів було використано метод рекурсивного спуску, що дозволило коректно враховувати пріоритет операцій та підтримувати вкладені вирази. У створеному інтерпретаторі реалізовано підтримку основних операторів мови Small BASIC, зокрема PRINT, INPUT, IF THEN, FOR/NEXT, GOTO, GOSUB/RETURN та END. Для реалізації циклів і підпрограм було використано структури даних Stack, а для роботи з мітками — TreeMap, що забезпечило правильне керування потоком виконання програми. У процесі тестування було перевірено роботу арифметичних операцій, умовних операторів, вкладених циклів, викликів підпрограм, а також введення та виведення даних. Усі тестові приклади були успішно виконані, що підтверджує правильність реалізації інтерпретатора. Також у межах додаткового завдання було досліджено методологію Twelve-Factor App та проаналізовано можливість її застосування до консольних CLI-застосунків. У проєкті було реалізовано керування залежностями через Gradle, конфігурацію через змінні середовища, систему логування та стандартизований процес збірки і запуску. Використання принципів Twelve-Factor App дозволило зробити проєкт більш структурованим, переносимим і зручним для подальшої підтримки та розвитку. У результаті виконання лабораторної роботи було отримано практичні навички розробки інтерпретаторів мов програмування, організації структури програмного проєкту та використання сучасних підходів до створення програмного забезпечення.
